# 무료 영상 채점 재설계 (2026-09-16)

## 결론

기존의 "작은 스크린샷 -> VLM이 득점 추측 -> 합산"은 정확한 자동 채점에 적합하지 않다.
처리 시간을 늘려도 영상에 없는 착지/아웃 판정 근거가 생기지는 않는다.
목표를 **근거가 연결된 랠리 초안 생성 + 필요한 구간 검토 + 결정론적 점수 합산**으로 바꾼다.
유료 API는 사용하지 않는다. 기존 Gemma와 로컬 FFmpeg/Pillow만 사용하는 v2를 먼저 적용한다.

## 기존 코드의 문제

- 1초 간격, 높이 160px 프레임을 4장씩 붙여 빠른 접촉과 종료 장면을 놓침.
- 긴 영상은 프레임 수 제한 때문에 샘플 간격이 더 벌어짐.
- 선수의 이름만 다음 단계에 전달하고 기준 프레임의 외형/박스는 전달하지 않음.
- 창별 득점을 즉시 합산하여 중복, 렛, 미검출, API 실패를 일관되게 처리하지 못함.
- 추정치가 21점 형태가 되면 영상이 남아 있어도 중단함.
- 모델 자체 확신도를 점수 정확도의 확률처럼 표시함.

## 선택한 구조

```text
YouTube + 경기 구간 + 시작 점수
  -> 로컬에 해당 구간만 캐시 (최대 30분, Render로 영상 전송 없음)
  -> 기준 프레임 4명 매핑 -> 팀 A/B 외형 앵커
  -> 2 fps 고정 1차 탐색, 인접 창 중첩
  -> 득점/렛 후보 전후 원본을 8 fps로 독립 재검토
  -> 시간축 이벤트 병합 -> 서브/종료 연결 -> 랠리/미확인 구간 장부
  -> 영상 타임스탬프 링크 + 사용자 수정
  -> 서버가 수정된 장부를 합산 -> 명시적 확인 -> 기존 경기/ELO 등록
```

네 선수의 매 프레임 신원 추적을 점수 계산의 필수 조건으로 두지 않는다. 점수에는 팀 구분이
중요하다. A팀이 항상 화면 아래에 있다고 가정하지 않으며, 같은 옷/코트 체인지/가림으로
팀이 불확실하면 검토 대상으로 남긴다. 현재 방식은 **외형 앵커를 사용하는 VLM 관찰**이며,
ByteTrack 등 전문 추적 모델을 이미 적용했다는 뜻은 아니다.

## 구현한 v2

- `app/review_frames.py`: 구간 캐시, 로컬 재추출, 시각 표기, 기준 이미지 박스, 종횡비 유지.
- `app/providers/rally_review.py`: 점수 누계 없이 이벤트만 요청, 2단계 분석, API 실패 구간 보존.
- `app/rally_ledger.py`: 중복 병합, 충돌 미확정, 서브 없는 종료/종료 없는 서브/컷 처리.
- `lib/video-review.js`: 클라이언트 최종 점수를 신뢰하지 않고 서버에서 재계산.
- 홈페이지: 경기 시작/끝 초, 시작 점수, 랠리별 A/B/무득점 수정, 누락 구간 양 팀 득점 입력.
- 선수 매핑과 같은 작업 소유자/admin 권한을 적용. 검토자/수정 내용/시간을 결과에 보관.
- 모든 미확인 구간과 최종 확인 체크가 해결되어야 등록. 기존 v1 결과는 호환 유지.
- 60초마다 작은 heartbeat. PostgreSQL에서는 잠금 시각만 갱신하고 그림은 전송하지 않음.
  heartbeat가 화면 변경으로 인식되어 이미지를 다시 내려받는 것도 방지.
- 같은 작업의 이전 시도 결과, 이미 완료/취소된 작업의 늦은 결과는 새 worker에서 거부.

이미지는 요청 전체 JSON을 포함해 40,000 bytes 안에 맞춘다. 한 장의 패널을 240px 미만으로
뭉개기보다는 중첩된 작은 묶음으로 나눈다. 최소 해상도에서도 맞지 않으면 미확인 구간으로 남긴다.
결과도 40,000 bytes 이내이며, 용량이 크면 설명을 줄이지 랠리 행 자체를 자르지는 않는다.

한 게임은 최대 30분. 홈페이지는 2,400개 1차 프레임(2 fps로 20분) 예산을 전달한다.
예산 뒤의 구간은 더 성긴 샘플로 숨기지 않고 미확인 구간으로 표시한다.
모델 호출은 최대 800회이며 세 창이 연속 실패하면 나머지는 검토로 넘긴다.
8 fps 재검토는 종료 후보 주변 1초 구간이다. 전 영상의 콕 궤적을 추적하는 기능은 아니다.

## 아직 구현하지 않은 더 강한 경로

1. **점수판이 있는 영상: 로컬 OCR 우선.** 사용자가 점수판 영역과 A/B 방향을 지정하면
   해당 영역의 연속 판독, 시간별 다수결, 증감/리셋 검증으로 채점한다. 랠리 추론은 검증 보조다.
   음성으로 점수를 말하는 영상은 점수 호명도 보조 관측으로 쓸 수 있지만 별도 로컬 ASR이 필요하다.
2. **점수판 없는 영상: 전문 CV로 후보 생성.** 선수 박스+ByteTrack, 코트 좌표 보정,
   TrackNetV3 또는 WASB 셔틀 궤적, 타격/정지/서브 후보를 뽑아 Gemma의 질문 범위를 좁힌다.
   셔틀 검출 정확도는 득점 판정 정확도가 아니며, 동호회 복식 영상으로 재검증해야 한다.
3. 현재 GT 1030 2GB 환경에 대형 모델/학습 가중치를 무리하게 자동 설치하지 않았다.
   CPU 실행 가능 여부, 가중치/라이선스, 메모리와 처리시간을 먼저 측정한 뒤 추가한다.
   논문 수치만 보고 학습되지 않은 동호회 카메라 영상의 정확도를 보장하지 않는다.

앞으로 촬영하는 영상이라면 **카메라에 읽히는 점수판을 함께 찍는 것**이 가장 확실한 개선이다.
기존 점수판 없는 영상에서는 사람이 검토할 구간을 줄이는 것이 현실적인 무료 목표다.

## 규칙과 불확실성

랠리 승리 팀이 다음 서브권을 가지지만, 다음 서브 하나만 보고 이전 득점을 확정하면 안 된다.
편집, 렛, 경기 전 연습, 다른 세트, 서브 실수, 마지막 랠리가 예외다. v2는 다음 서브를 자동으로
1점으로 환산하지 않는다. 두 분석이 일치해도 확률로 보증하지 않고 후보로 취급한다.
사용자가 고른 구간이 한 게임인지, 시작 점수가 맞는지, 누락 랠리가 없는지도 확인해야 한다.
동호회 변형 규칙을 허용하므로 21점 모양만으로 영상을 종료하지 않는다.

## 검증 상태와 다음 평가

자동 테스트는 코드의 중복/누락 처리, 서버 권한·합산·보관, 업로드 크기, heartbeat와 화면 동작을
검증한다. 실제 영상 채점 정확도를 뜻하지 않는다. 짧은 실제 YouTube 구간에서 Gemma 무료 경로의
실행은 확인했지만, 정답 라벨이 없어 정확도 수치는 제시하지 않는다.

다음 평가는 같은 동호회 영상 3개 이상에 서브 시각/종료 시각/승리 팀/렛/편집/최종 점수를
사람이 라벨링하고 고정한 뒤 v1/v2를 비교한다. 지표는 다음과 같다.

- 랠리 누락률과 중복률, 승리 팀 정확도(미확정 비율 별도).
- **경기 최종 점수 완전 일치율**. 프레임 검출 F1로 대신하지 않는다.
- 사람의 수정 횟수, 검토 소요 시간, 모델 호출 수/전송 bytes, 처리시간.
- 경기 시작/끝이 잘린 영상, 코트 변경, 동점 연장, 렛, 다른 코트 선수가 들어오는 경우.

평가 전에는 완전 자동 등록을 활성화하지 않는다. 유료 모델 호출/자동 학습도 없다.

## 실행

기존 worker를 종료한 뒤 사용하던 Python 가상환경에서:

```powershell
cd E:\github\badminton-elo-ranking\video-score-service
python -m pip install -r requirements.txt
python worker.py
```

새 링크로 작업을 만들고 4명을 연결한다. 필요한 경우 경기 구간과 시작 점수를 지정한다.
검토 화면에서 각 구간을 확인하고 미확인 항목을 해결한 뒤 저장한다. 이전 결과를 새 방식으로
분석하려면 새 작업이 필요하다. OpenAI 키는 읽거나 사용할 필요가 없다.

새 점수 요청의 필드: `startSeconds`, `endSeconds`(없으면 영상 끝), `startScoreA`, `startScoreB`,
`maxFrames`. 결과 `analysisVersion: 2`의 `review.rallies`는 삭제하지 않고 그대로 보관한다.
확정 요청은 `{ review: { decisions: { r1: { winner: "A" }, r2: { scoreA: 2, scoreB: 1 } },
extraPoints: { scoreA: 0, scoreB: 0 }, coverageConfirmed: true } }` 형식이다.
`rally`는 winner, `gap`은 해당 구간의 득점 수다. 최종 점수 직접 전달은 반영하지 않는다.

## 참고한 1차 자료

- [TactiPlay (2026)](https://arxiv.org/html/2607.27125v1): 아마추어 단식 영상의 랠리 기반 검토.
  109개 랠리에서 분할 정확도 75%, 분할 성공 랠리의 승리/사유 정확도 68%를 보고했고,
  사용자 연구에는 사람이 보정한 라벨을 사용했다. 복식 자동 채점 정확도의 증거가 아니다.
- [TrackNetV3 저자 코드](https://github.com/qaz812345/TrackNetV3): 셔틀 추적/가림 보완 후보.
- [WASB 원 논문](https://papers.bmvc2023.org/0310.pdf): 여러 종목의 공 검출/추적.
- [ByteTrack 저자 코드](https://github.com/FoundationVision/ByteTrack): 박스 연결 기반 다중 객체 추적.
- [BWF Laws 공식 보관본, 11.3/14](https://system.bwfbadminton.com/documents/folder_1_81/Regulations/Laws/Part%20II%20Section%201A%20-%20Laws%20of%20Badminton%20-%20May%202017.pdf): 랠리 득점·서브와 렛.
  보관본을 최신 규칙 전체로 간주하지 않으며, 클럽의 실제 경기 방식은 사용자 확인을 따른다.
