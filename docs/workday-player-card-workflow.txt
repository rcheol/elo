Honey Serve Workday profile photo and player card workflow
Last updated: 2026-10-21

Use this exact workflow for future player-card requests. Do not rediscover the
browser, screenshot, crop, prompt, compression, or push path from scratch.

1. Identify the player
   - Fetch live state from https://honeyserve-elo.onrender.com/api/state.
   - Match the requested Korean player name to the player object.
   - First use the Workday/search id explicitly supplied by the user.
   - Otherwise use player.accountUsername from the live site. Do not require a
     dot or guess whether the account username looks like a Workday id.
   - Only if both are absent, ask for the search id before searching by name.
   - A different Workday id is an asset/search mapping, not a request to rename
     the Honey Serve login account.
   - Check existing profile photos and all requested card tiers before creating
     assets. Use the player's stored gender, not a guess from name or photo.

2. Connect to the requested browser (verified in-app path, 2026-10-15)
   - Current supported entry point verified on 2026-10-21: mcp__cua_repl.js.
     First call await cua.getState(), then bind the returned Workday tab with
     await cua.getTab(tabId, { browser: browserId }). Read its documentation.
     It supports the same playwright locators and downloadMedia method below.
     Reuse this connection; no legacy runtime bootstrap is needed when this
     tool is available. Browser/tab ids must come from the current inventory.
   - Use the user's exact existing Workday tab. Do not silently switch to Edge,
     create another login session, or move desktop windows to the foreground.
   - The successful in-app method uses mcp__node_repl.js and the installed
     browser plugin's public runtime, not native desktop automation:

     const { setupBrowserRuntime } = await import(
       'C:/Users/cheol.ryu/.codex/plugins/cache/openai-bundled/browser/26.1007.71326/scripts/browser-client.mjs'
     );
     const agent = await setupBrowserRuntime();
     nodeRepl.write(await agent.browsers.list());

   - Select the listed Codex In-app Browser with type "iab". Then list its tabs
     and get the existing Workday tab by its returned id. Do not hardcode ids:
     browser id "2" and tab id "1" were this session's values only.
   - Read await browser.documentation() and use only its supported APIs.
   - Reuse agent/browser/workday handles while they remain valid. If a tab goes
     stale, reacquire the tab from the same browser, not another browser.
   - The installed plugin version/path may change after an update. Locate its
     current public runtime when necessary; do not probe private transports.
   - A missing legacy cua tool does not mean the in-app browser is inaccessible.

3. Browser safety and recovery
   - For an explicitly requested Edge session, use the currently available
     browser tool and its documented connection method. Historical port 9333
     is not proof that a current session is reachable.
   - Do not use raw CDP, Win32 foreground automation, or hidden page APIs as a
     workaround for the supported browser connection.
   - If login or user action is required, report the observed page state and
     leave the requested tab available. Do not repeatedly reopen browsers.

4. Search Workday
   - Read workday.playwright.domSnapshot() before interacting.
   - In the verified Korean UI, click the button named "검색" (exact), then
     fill the combobox named "Workday 검색" with the search id and press Enter.
     Confirm those locators in the current DOM rather than assuming they exist.
   - Workday is slow. The first snapshot after Enter can still be the home page;
     wait for the search results and inspect again instead of submitting twice.
   - Verify the result name and email/id visually before using the photo.
   - Verified example: hojin59.kim returned HOJIN KIM with the matching account.
     Both search-field operation and the search-result screenshot succeeded.
   - Save a screenshot as proof, excluding unrelated contact/HR details. Leave
     the user's tab open; markHandoff() when work continues in a later turn.

5. Save the profile photo
   - Click the verified search-result name to open the person's profile. Wait
     for the profile heading, then click that person's employee-photo button.
     This opens the "larger image" alertdialog with a full-resolution image.
   - Locate the image by its exact alt text from the current DOM. Do not confuse
     it with the signed-in user's top-right avatar or a manager's photo.
   - Call locator.downloadMedia({ timeoutMs: 120000 }) on that image. This was
     verified for all three members on 2026-10-15, returning local JPEG paths.
   - If the image is still loading and an initial download times out, inspect
     the current DOM and image src again, then retry the same supported method.
     Do not switch to screen cropping or another browser merely for a slow load.
   - Copy the downloaded file to its identity path and inspect it with view_image.
     Close the photo dialog and verify it is closed before the next search.
   - If the page exposes no downloadable image, use a supported screenshot
     capture/crop path as permitted by the current tools and inspect the result.
   - If the verified profile has no photo, ask for a user-provided photo or an
     alternate Workday id. Do not use a placeholder or another person's image.
     A supplied local photo is a valid source; inspect it and record that source
     separately from Workday. Continue other members while awaiting the photo.
   - Save the final photo as surge-deploy/assets/player-photos/<identity>.jpg.
     Preserve useful facial detail; the former upload-size cap no longer applies.

6. Generate player cards
   - Use the built-in image_gen tool, not a custom script, for card generation.
   - References for each card:
     1. The saved profile photo
     2. The matching base figure card:
        - male-s-figure.jpg, male-a-figure.jpg, male-b-figure.jpg, male-c-figure.jpg
        - female-s-figure.jpg, female-a-figure.jpg, female-b-figure.jpg, female-c-figure.jpg
   - Use the prompt from docs/player-card-prompts.txt.
   - Keep the card Nendoroid / collectible figurine style. Use the profile photo
     only for stylized facial-design cues, not literal face copying.

7. Save and compress generated cards
   - Preserve the 2:3 aspect ratio. New cards use 520x780 JPEG at quality 90 for
     sharper high-density displays; old 260x390 assets need not be rewritten.
   - Profile photos can be optimized to at most 512x512 without upscaling.
     Strip source metadata and retain downloaded/generated originals locally.
   - Save as JPEG:
     surge-deploy/assets/player-cards/<identity>-s-figure.jpg
     surge-deploy/assets/player-cards/<identity>-a-figure.jpg
     surge-deploy/assets/player-cards/<identity>-b-figure.jpg
     surge-deploy/assets/player-cards/<identity>-c-figure.jpg
   - As of 2026-10-15, the user reports that the upload-size limit is removed.
     Do not enforce the former 40KB cap or split pushes one image at a time.
     Optimize JPEGs for web delivery without sacrificing facial detail solely
     to meet that old limit.
   - Inspect the final compressed files with view_image before committing.

8. Wire the assets into the site
   - Add a playerAssetProfiles entry in surge-deploy/app.js.
   - Include accountIds, workdaySearchIds, nameIncludes, photo, and
     figureCardTiers: ["s", "a", "b", "c"].
   - Run npm.cmd run check. In PowerShell, use npm.cmd, not npm, because npm.ps1
     can be blocked by execution policy.

9. Commit and push
   - Do not commit tmp/.
   - Commit only the related docs, app.js mapping, profile photos, card images,
     and asset tests. Preserve unrelated staged and unstaged changes.
   - Prefer the authorized Codex GitHub connector, verified as rcheol with push
     permission on rcheol/elo. Follow docs/github-push-workflow.txt for blob and
     tree verification, a non-forced ref update, and safe local synchronization.
   - Connector authentication is separate from Windows Credential Manager.
     Do not assume a numeric credential id is stale or delete credentials.
   - Verify the live app mapping and image bytes after Render auto-deploys.
